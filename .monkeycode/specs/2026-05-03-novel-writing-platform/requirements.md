# 需求文档

## 简介

一个基于 Web 的小说编写平台，支持多用户注册登录，管理员后台管理大模型 API 渠道和定价，普通用户和管理员都可以使用 AI 大模型辅助编写小说。系统内置初始额度，按 token 消耗计费，支持多种小说类型和角色设定。数据库使用 PostgreSQL。

## 术语表

- **平台**: 小说编写 Web 应用系统
- **管理员**: 拥有后台管理权限的用户，可配置 API 渠道、模型和定价
- **普通用户**: 注册登录后的普通用户，可使用编写功能
- **API 渠道**: 大模型服务提供商的接入点（如 OpenAI、Claude、智谱等）
- **额度**: 用户账户中可用于消耗的金额，单位为人民币（元）
- **Token**: 大模型处理的文本单位
- **攻受文**: 耽美/BL 类型小说
- **男女文**: 言情/BG 类型小说
- **角色设定**: 小说中男主角和女主角的性格、名字等属性配置

## 需求

### 需求 1: 用户注册与登录

**用户故事:** 作为访问者，我想要注册账号并登录系统，以便使用小说编写功能。

#### 验收标准

1. WHEN 访问者提供有效邮箱和密码并点击注册，平台 SHALL 创建新用户账户并返回注册成功
2. WHEN 用户提供已注册的邮箱和正确密码并点击登录，平台 SHALL 验证凭据并返回有效的会话令牌
3. IF 用户输入错误的密码超过 5 次，平台 SHALL 锁定该账户 15 分钟
4. WHILE 用户已登录，平台 SHALL 在每次请求中验证会话令牌的有效性

### 需求 2: 管理员权限授予

**用户故事:** 作为已登录用户，我想要通过访问管理员接口成为管理员，以便使用后台管理功能。

#### 验收标准

1. WHEN 已登录用户访问管理员授权接口并提供有效的管理员授权码，平台 SHALL 将该用户角色升级为管理员
2. WHILE 用户角色为管理员，平台 SHALL 允许访问管理员后台界面
3. IF 非管理员用户尝试访问管理员后台，平台 SHALL 拒绝访问并返回 403 错误

### 需求 3: 管理员 API 渠道管理

**用户故事:** 作为管理员，我想要添加和管理大模型 API 渠道及密钥，以便为用户提供 AI 编写功能。

#### 验收标准

1. WHEN 管理员在后台添加 API 渠道，平台 SHALL 保存渠道名称、API 密钥、基础 URL、支持的模型列表和渠道状态（启用/禁用）
2. WHEN 管理员添加预置渠道（OpenAI、Claude、智谱、文心、通义等），平台 SHALL 自动填充对应渠道的基础 URL 和可用模型列表
3. WHEN 管理员添加自定义渠道，平台 SHALL 允许手动配置基础 URL 和自定义模型列表，支持添加多个自定义渠道
4. WHEN 管理员编辑 API 渠道，平台 SHALL 更新对应渠道的配置信息
5. WHEN 管理员删除 API 渠道，平台 SHALL 将该渠道标记为不可用并停止新请求的路由
6. WHILE API 渠道列表存在，平台 SHALL 在后台界面展示所有渠道的状态（启用/禁用）和调用统计

### 需求 4: 管理员模型定价管理

**用户故事:** 作为管理员，我想要设置每个模型的 token 价格，以便系统按用量计费。

#### 验收标准

1. WHEN 管理员设置模型价格，平台 SHALL 保存每百万输入 token 价格和每百万输出 token 价格（单位：元）
2. WHILE 模型价格已配置，平台 SHALL 在用户消耗 token 时按该价格计算费用
3. WHEN 管理员修改模型价格，平台 SHALL 对修改后的新消耗按新价格计费

### 需求 5: 用户初始额度

**用户故事:** 作为新注册用户，我想要获得初始额度，以便立即体验 AI 编写功能。

#### 验收标准

1. WHEN 新用户完成注册，平台 SHALL 为该用户账户充值 2.00 元初始额度
2. WHILE 用户账户有余额，平台 SHALL 允许用户发起 AI 编写请求
3. IF 用户账户余额不足以支付当前请求的预估费用，平台 SHALL 拒绝请求并提示余额不足

### 需求 6: AI 编写功能（管理员配置可用时）

**用户故事:** 作为普通用户，我想要在管理员已配置 API 渠道的情况下使用 AI 编写，而无需自行添加 API 密钥。

#### 验收标准

1. WHILE 管理员已启用至少一个 API 渠道，平台 SHALL 允许普通用户直接使用 AI 编写功能
2. WHEN 普通用户发起编写请求，平台 SHALL 从管理员配置的渠道中选择可用模型处理请求
3. IF 管理员未配置任何可用 API 渠道，平台 SHALL 提示用户自行添加 API 密钥

### 需求 7: 用户自定义 API 密钥

**用户故事:** 作为普通用户，我想要添加自己的大模型 API 密钥，以便在管理员未配置渠道时使用 AI 编写功能。

#### 验收标准

1. WHEN 用户在个人设置中添加 API 密钥，平台 SHALL 加密保存密钥并关联到用户账户
2. WHILE 用户已添加有效的 API 密钥，平台 SHALL 优先使用用户自己的密钥处理编写请求
3. WHEN 用户删除 API 密钥，平台 SHALL 从系统中移除该密钥的存储

### 需求 8: 按 Token 计费与消耗记录

**用户故事:** 作为用户，我想要查看额度消耗记录，以便了解费用明细。

#### 验收标准

1. WHEN 用户完成一次 AI 编写请求，平台 SHALL 根据实际消耗的 token 数量和模型价格计算费用
2. WHILE 用户账户有消耗记录，平台 SHALL 在个人中心展示每次请求的日期、模型、输入 token 数、输出 token 数和费用
3. WHEN 用户查询账户余额，平台 SHALL 显示当前可用额度和累计消耗金额

### 需求 9: 小说类型选择

**用户故事:** 作为用户，我想要选择小说类型（攻受文/男女文等），以便 AI 根据类型生成合适的内容。

#### 验收标准

1. WHEN 用户创建新小说，平台 SHALL 提供小说类型选项（攻受文、男女文）
2. WHILE 用户选择小说类型，平台 SHALL 将该类型传递给大模型作为生成提示的一部分
3. WHEN 用户切换小说类型，平台 SHALL 更新后续 AI 生成的内容风格

### 需求 10: 角色设定配置

**用户故事:** 作为用户，我想要配置男主角和女主角的性格和名字，以便 AI 生成符合设定的内容。

#### 验收标准

1. WHEN 用户配置男主角设定，平台 SHALL 保存男主角的名字和性格特征
2. WHEN 用户配置女主角设定，平台 SHALL 保存女主角的名字和性格特征
3. WHILE 角色设定已配置，平台 SHALL 在每次 AI 编写请求中包含角色设定信息
4. WHEN 用户修改角色设定，平台 SHALL 对后续生成使用新的角色设定

### 需求 11: 章节管理

**用户故事:** 作为用户，我想要管理小说的章节，以便组织和编写长篇内容。

#### 验收标准

1. WHEN 用户创建新章节，平台 SHALL 生成章节序号、标题和空白内容区
2. WHILE 用户编写章节，平台 SHALL 提供 AI 续写、AI 润色、AI 扩写功能和手动编写模式
3. WHEN 用户保存章节，平台 SHALL 自动保存内容并记录修改时间
